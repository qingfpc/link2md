# link2md 项目计划

把一条链接变成可检索的文字，写进 Obsidian，作为个人知识库的原料。

路径是：粘贴分享文案或 URL → 识别平台并抽出正文（文章直接抽取，音视频优先字幕，否则转写）→ 可选地用大模型整理成摘要、要点和标签 → 一篇 Markdown 笔记落在仓库里。后面的检索和问答都建立在这些笔记上。

本文对照 `main` 上的 v1（squash commit `4dc7380`）编写。勾选表示这件事已经做完，并且有对应的代码或实测记录。

## 以后：知识库能查、能问

笔记先积累在 Obsidian 里。这一阶段给同一批笔记加查询，不改变「一条内容一篇 Markdown」的存法。

- [ ] SQLite 全文检索：按标题、正文、作者、平台、标签、URL 查找，结果能打开对应笔记
- [ ] 语义检索：对笔记做向量索引，用一句话找相关笔记
- [ ] 基于知识库的问答：问题先检索相关笔记，再让模型按笔记内容回答，并给出笔记路径
- [ ] 索引能随新增和 `--update` 更新，删除笔记后查询不再返回它

### 完成标准

- 已保存的笔记可以用关键词查到
- 一句自然语言能找出主题相关的几篇笔记
- 问答的依据能回到具体笔记，仓库里的 Markdown 仍是源文件

## 风险

- **平台反爬。** B 站匿名请求在数据中心网络上会返回 HTTP 412，字幕接口还经常要求登录。微信会出验证页。抖音和小红书对未登录、高频访问更严。应对是 Cookie、明确报错、失败重试，以及个人使用的低频保存。
- **页面和接口会变。** 小宇宙的 `__NEXT_DATA__`、微信的 `#js_content`、yt-dlp 的字幕字段（`ai-zh` 目前在 `subtitles` 里）都可能改版。解析器保持一平台一个模块，并用固定夹具测试结构。DeepSeek 的模型名已经从 `deepseek-chat` 换成 `deepseek-flash`，默认值写在配置里，方便再改。
- **费用。** DashScope 按音频时长计费，DeepSeek 按 token 计费。长播客会先下载再转写，模型还会分段调用。`link2md doctor` 在缺密钥时跳过这两步并仍保存原文；验收时先用短样本看质量和账单。
